## Security and cost controls

All enhanced actions pass existing verified authentication, project and live organization role checks, per-user admission, and revision/evidence CAS. Viewers can read; mutation controls remain server-side. Owner-manager only changes scoring weights; authorized reviewers approve source metadata and knowledge reuse. Final signoff checks a current quality input hash and unresolved high/critical findings. Metadata mutation is a service-only RPC and conservatively invalidates organization project evidence epochs. Existing document RLS and private storage remain intact. No new public write policy or storage bucket.

AI writing is opt-in per request, uses the existing configured compliance model/key and fixed OpenAI endpoint, `store:false`, no tools, untrusted document boundary, structured output, server-validated source IDs, 24,000 input characters, 2,000 output tokens, 35-second timeout, existing leased background jobs, three-attempt ceiling and existing per-user/org/global draft admission. Every provider attempt also consumes organization admission. Result records prompt version, configured model, usage and duration; estimated dollar cost remains unknown without current account pricing. Output is unverified until human review and never overwrites saved text without acceptance. No live AI call is necessary to use demo, scoring, audits, reports, metadata or assembled drafts.

The workspace retains its existing access policy: workspace editing/export/assembly does not debit emailed-proposal allowances. New AI assistance is bounded by workspace quotas, not a newly invented Stripe credit mapping. Do not market a new paid entitlement until plan policy is explicitly agreed and tested. Existing card-required 14-day trials and allowance enforcement are unchanged. Provider privacy/Netlify secret-scope limitations previously accepted remain unchanged.

No customer text is sent to analytics. Demo emits ephemeral content-free DOM events only, with no remote collector/session identifier. Owner project metrics derive from existing revisions/events/jobs and show milestones, failure states and queue-inclusive durations. **Global anonymous-demo → signup → paid conversion aggregation is not implemented:** no existing analytics collector was found. Do not claim a complete conversion dashboard. Outcomes are private, recorded in immutable project revisions; future statistical recommendations require sufficient consented data and validation.

## Release / rollback

Before production: complete hosted authenticated journey, applied-migration checks, RLS/role tests, browser QA, provider sandbox validation if enabled, reviewed policy/claims, build and full regressions; obtain explicit production approval. Current scope limitations must be reviewed, not silently waived.

Rollback: disable PROPOSAL_INTELLIGENCE_ENABLED and redeploy the previous verified production commit. Preserve metadata, new source versions and project history; no destructive down migration. Existing project state tolerates added keys. If public demo rollback is needed, restore prior demo/home build. Keep proposal email disabled. Reverting code alone does not undo changed source metadata or audit decisions; review those records rather than deleting them.
