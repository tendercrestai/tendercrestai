# Compliance preview architecture assessment (2026-10-13)

Inspected every main repository file at a3d2de9, the branches and all four PRs. Secure upload PR #1 and status/new-attempt PRs #2/#3 are merged. Reuse their private rfp-documents bucket, immutable rfp_uploads metadata, PDF/DOCX/TXT limits, verified bearer authentication and proposal submission ledger. Do not duplicate or change billing or submission.

Main is static HTML/ES modules, Netlify CommonJS functions and Supabase REST/Auth/Storage. Browser extraction is for review; submit-proposal verifies ownership, size, hash and file signatures before creating an Airtable Companies trial or Proposals Pipeline record. Airtable performs AI drafting, quota formulas and email delivery; Stripe webhook updates company subscriptions. No direct AI provider credentials/client or organization membership schema exists in main.

Open PR #4 (feature/evidence-grounded-proposals) introduces a private evidence library, runtime browser configuration and an Airtable engine revision. It is deliberately not incorporated wholesale. New compliance tables use distinct names; manual evidence references do not claim integration with the unmerged library. Its configuration changes may cause small navigation conflicts when rebasing. No existing customer table is destructively changed.

Implementation decision: optional /compliance.html workflow, verified server-side extraction, immutable source segments with PDF physical page indexes; DOCX/TXT page numbers unavailable. Prepare, review, then analyze bounded chunks in separate requests to fit function durations. Structured output is validated against exact source excerpts; source identity/page/section comes from the server, never the model. AI has no evidence or compliance-status authority. Chunk results and review rows persist in Supabase. Atomic service-only RPCs handle deduplication, daily reservations, leases, retries and completion. Owner-only RLS preserves the existing authorization boundary; response-owner labels do not grant access. Organization-wide collaboration requires a separately reviewed membership model.

Integration risks: production upload migration/bucket may not yet be activated; permissive Storage policies must be audited; preview auth/browser/server settings must agree; original proposal endpoint targets production Airtable, so preview tests must never submit to it. Server PDF parser adds a pinned dependency and needs Netlify Node 22+. Large/scanned/mixed PDFs must expose extraction gaps. PDF pages are physical file pages, not printed folio labels. DOCX headers, footers, images and drawings may contain additional requirements; extracted body text is marked partial when unsupported content exists. Prompt separation and citation validation reduce injection/hallucination risks but human review remains necessary. Exact duplicates can merge; similar/conflicting amendment requirements stay separate for reviewer resolution.

No live migrations, Airtable runs, Stripe calls, customer documents or production deploys are authorized as part of implementation. Current environment cannot reach its network proxy via shell; dependency installation and live SQL/browser tests may need a functioning preview environment. Connector access allows repository reads/writes. Local baseline is a reconstructed main snapshot because git clone is unavailable; remote commits must parent the original GitHub SHA.
