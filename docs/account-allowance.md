# Account proposal allowance

My Account (`/auth.html`) shows the linked emailed-draft service plan, current allowance, used/in-progress and remaining proposals, and next billing boundary in the customer's browser time zone. Trials show expiry and no within-trial reset. Renewal is explicitly conditional on successful payment. Missing plans, inactive/expired periods and synchronization failures never display an invented balance; a refresh button retries live reads. Pending requests are ignored after logout or account changes.

`GET /.netlify/functions/account-usage` verifies the Supabase session and resolves the billing account using only its verified email, matching the submission workflow. It accepts no client company/user/email selectors, denies duplicate billing matches, returns no internal account IDs and sends no-store headers. Organization members whose verified email differs from the linked billing email do not gain access to another account's balance; support must resolve billing-email mismatches through existing account procedures.

Read-only accounting uses the existing `credits.entitlement`, linked legacy Airtable history and current non-released Postgres reservations. Matching queued terminal failures are excluded just as the submission path releases them; mismatched markers remain counted. No credit is reserved/released, no subscription is changed, and no email, payment, database migration or new secret is required. Submission remains the authoritative atomic quota enforcement point; the displayed balance is a timestamped snapshot and concurrent submissions can change it.

Server configuration reuses SUPABASE_URL, SUPABASE_PUBLISHABLE_KEY, SUPABASE_SERVICE_ROLE_KEY and AIRTABLE_PAT. The isolated site intentionally has no Airtable credential; it should show a recoverable usage-unavailable state. Never copy a production billing credential into staging merely to clear that test.

Validation: account backend tests cover live/legacy usage, trial allowance, expiry, failed-marker integrity, authentication, identity-selector rejection, no-plan state and a complete active-account request. Chromium fixtures cover mobile/desktop display, refresh, trial expiry, exhausted allowance, no-plan CTA and clearing on logout.
